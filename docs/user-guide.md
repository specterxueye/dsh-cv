# 简历大师 · 用户手册

> 对应版本：dsh-cv 0.4.0 · **第一次安装/上手看 [安装与使用](安装与使用.md)** · 配套文档：[README](../README.md)

本手册面向最终用户（求职者），按完整使用流程说明操作步骤。插件适用于中文求职场景，支持技术开发岗、央国企等方向的定制简历。

---

## 1. 准备工作

| 项目 | 说明 |
|------|------|
| 运行环境 | DeepSeek Harness（DSH），已挂载 4 个技能：`cv-intake` / `resume-writing` / `interview-pitch` / `mock-interview`（安装与自检见 [安装与使用](安装与使用.md)） |
| Node.js | ≥ 16（用于生成器/校验器脚本） |
| magicv.art 账号 | 用于简历渲染与导出（https://magicv.art） |

聊天方式触发：说出「帮我写简历」「分析这个 JD」「帮我建档」「按这个 JD 选项目」「生成 magicv JSON」等即可自动加载技能。

> 装完不确定是否成功？跑 `pwsh -NoProfile -File scripts\install.ps1` 会打印自检：技能联接 **4/4 就位** 即正常；缺哪个技能，会话里就用不了哪个功能。

## 2. 建立人物档案（第一次使用必做）

档案是之后所有简历的事实来源，只需建一次，可跨会话复用、跨岗位使用。

### 2.1 提供信息（拷问式，不用你组织语言）

插件会加载 `cv-intake` 技能，按两种方式之一采集：

**方式一：给现成材料（推荐，省最多轮）**
已有简历（PDF/Word/图片）、成绩单、证书原件、实习单位材料、个人项目仓库地址——给路径即可。插件会派子代理反解析，抽出的每条事实**逐条回显给你确认**后才采信（旧简历里常有夸大或过期信息，不会静默照抄）。

**方式二：回答 frontier 提问（没材料时）**
分 7 轮推进，每轮把当前能问的**整批列出**，每题都带推荐答案或选项，例如：

```
❓ Q3 - 实习中你的角色？   ➡️ 推荐：核心开发（模块负责人）
❓ Q4 - 有量化产出吗？     ➡️ 推荐：有具体数 → 开发记录/接口数/页面数
```

你回一句「1✅ 2 改成组长 3 跳过」即可，**不必写整段话**；每轮都可以答"跳过/没有"。涉及以下五类：

1. **基本信息**：姓名、出生年月、所在城市、联系方式、政治面貌（投央国企必填）
2. **教育经历**：学校、专业、学位、起止时间、GPA/排名、主干课程、荣誉
3. **实习/工作经历**：公司、职位、时间、角色（你是否主导）、具体负责事项、量化产出（如「覆盖 20+ 页面」「127 条开发记录」）
4. **项目经历**：名称、级别（国家级/省级/校级）、角色、时间、技术栈或方法、成果指标
5. **校园经历、证书奖项、技能、自我定位**

> 能机器查的（成绩单 GPA、证书、项目仓库提交量与依赖）插件会**自己派子代理去查**，不会把"你自己翻一下"推回给你。

### 2.2 产出

- `users\<用户名>\<名字>-事实基线.json`：全部事实 + 来源。**每条事实必须能溯源到你提供的信息或材料文件**；无法确认的会标注「待确认」。
- `users\<用户名>\<名字>-画像.md`：卖点（3-5 个）、定位语、可迁移技能、避雷点（内部参考，不进入简历正文）。

> 注意：**待确认的事实不会写入简历**。如果你希望某条信息使用，先提供来源。

## 3. 提供招聘要求（JD）

- **文字 JD**：直接粘贴全文。
- **图片 JD**：提供图片路径；插件自动识别分析。识别后**会列出不确定项请你确认**，不会静默猜测。

插件输出《JD 理解卡》：

| 栏目 | 内容 |
|------|------|
| 硬性要求 | 学历、年限、技术栈等必备条件 |
| 软性要求 | 沟通、协作、抗压等 |
| 加分项 | 证书、项目、爱好等 |
| 关键词表 | 简历中将命中的岗位词 |
| 缺口清单 | ★ 要求具备但你材料中没有的能力——如实列出，并给出处理策略 |
| 公司风格 | 央国企 / 互联网 / 外企 / 初创（影响措辞与版式） |

**缺口的诚实处理策略**（不会编造）：挖掘相近经历 / 建议补充材料 / 明确不写。

## 4. 生成定制简历

### 4.1 先按 JD 取舍项目（写之前先选）

候选池 = `项目素材库.md` 里的全部项目 ＋ 蓝本里没显示的项目。插件按**六维打分**（关键词命中 / 职能同型 / 级别真实性 / 角色主导 / 可量化可溯源 / 差异化）给出一张表：

| 项目 | 合计 | 建议 |
|---|---|---|
| LPL 赛事数据客户端 | 12 | ✅ 点亮·置顶 |
| 目标检测课程设计 | 7 | ✅ 点亮 |
| 图书管理系统 | 3 | ⏸ 收起（**不删除**，换岗位可切回） |

每项都会写清**命中了 JD 的哪一条**与页数影响，你可以逐项改判。**收起 ≠ 删除**；你明确排除的经历（社会实践等）永不进池；JD 要求但候选池里没有的，进《缺口清单》如实告知，不会为凑关键词硬塞。

> 重要：这一步的取舍只是**方案输入**，还要在下一步的《改动申请单》上得到你的明确批准，才会真正改简历。

### 4.2 写作策略（生成前先看，可要求调整）

插件会先输出写作策略供你审阅：

- 经历排序与详略（按岗位相关性）
- 关键词放置与加粗计划
- 技能分层（第一/二/三梯队）
- 自我评价 3 条（结论+论证）
- 缺口处理
- 一页裁剪清单

确认或提出修改后进入生成。

### 4.3 生成与校验

```powershell
node "scripts\build-resume.mjs" --profile <事实基线.json> --strategy <写作策略.json> [--out <输出.json>]
node "scripts\validate-resume.mjs" <输出.json> [--strict]
```

校验器检查：必填字段、菜单-数据键一致、HTML 结构、UUID、`autoOnePage`、内容真实性标记。**校验不通过不交付。**

### 4.4 交付物

- 简历 JSON（magicv 格式，文件名：`<姓名>-<岗位>-<学校>.json`）
- 《写作说明》：关键词命中、来源说明、缺口清单、优化清单自检结果（✅/⚠️/❌ + 原因）

## 5. 导入 magicv.art

1. 打开 https://magicv.art/app/dashboard/resumes
2. 导入/新建 → 选择生成的 JSON 文件
3. 选择模板渲染（`templateId: classic`，`autoOnePage` 已开启）
4. 微调细节后导出 PDF / 图片

**一页验收（硬标准）**：判据是 magicv **自己画的「第N页结束」标记**（y ≈ 1073.6px = A4 页高 1123 − 上下页边距 2×25），可运行 `scripts\render-measure3.cjs` 判定。**`render-height.mjs` 量的是预览容器（恒 1750px），`autoOnePage` 开关也不改变预览渲染——两者都不是页数判据**。超页 → 回插件按「裁剪清单」迭代：① 删无效内容 ② 精炼措辞 ③ 按岗位相关性裁剪 ④ 收起低相关项目（`visible:false`，未显示≠删除）；**不许靠压行距或关闭自我评价达标**。

---

## 6. 迭代与诊断

- 修改 → 再校验 → 再测量，**直到优化清单全绿**（或明确知道哪条做不到、原因是什么）。
- 人工微调后可在对话中请插件「以此版本为基线继续优化」。
- 新发现的事实会在下次建档时回填事实基线（保持多份简历事实一致）。

## 7. 多岗位版本

一份档案可产出多份岗位定制简历，互不覆盖：

- 每份写入 `users\<用户名>\output\`，文件名含岗位方向
- 切换岗位可对照《分岗位规则》：技术岗强调项目深度与技术栈；央国企强调稳定性/荣誉/政治面貌与真实政务项目；数据可视化岗前置 ECharts/交通局项目等
- 版本差异说明随写作说明交付

## 8. 常见问题

**Q1：图片 JD 识别不出来怎么办？**
插件会列出不确定项；如仍无法识别，直接粘贴文字即可。识别依赖视觉桥可用性（DSH 环境）。

**Q2：简历写不满一页 / 超过一页？**
**一页装下是硬标准**（外部来源虽有"技术岗可两页"的说法，插件一律按一页交付）。超页按顺序处理：① 删无效内容（重复信息、装饰词、组件级简单功能）② 精炼措辞（不为对齐模板砍真数据）③ 按岗位相关性裁剪（次要项目详述 > 低相关课程；核心经历不砍）④ 收起低相关项目（`visible:false`，随时可切回）。**装不下会如实告诉你"要一页须收起哪一项"**，由你裁决——不会偷偷压行距、关自评或藏项目来假装达标。不足一页说明信息量不足，建议补充真实材料。

**Q3：某岗位要求的能力我没有，会怎么写？**
如实进入缺口清单：挖掘相近经历 / 建议补充材料 / 明确不写。插件不会编造或粉饰（真实性铁律）。

**Q4：简历里的数字是编的吗？**
不会。每个数字可溯源到事实基线的来源；无据不写。

**Q5：换电脑 / 换目录怎么用？**
clone 后运行 `pwsh -NoProfile -File scripts\install.ps1` 即可（自动设置路径、建立技能联接、渲染注册壳），无需手工修改任何路径；旧机的 `users\<用户名>\` 拷过来即可续用历史档案。

**Q6：我的个人数据会被上传到仓库吗？**
不会。个人数据仅存本机 `users\<用户名>\`，仓库 `.gitignore` 已排除。

**Q7：装完怎么确认成功？技能在会话里看不见怎么办？**
跑 `pwsh -NoProfile -File scripts\install.ps1`，末尾自检应显示 **3/3 通过、技能联接 4/4 就位**；缺技能就重跑脚本，然后**新开一个会话**（技能目录与环境变量在新会话才完全生效）。安装、自检命令、卸载与其余故障处理见 [安装与使用](安装与使用.md)。

---

## 9. 数据与隐私

- 你的事实基线、画像、简历成品只保存在本机 `users\<用户名>\` 目录。
- 写作规律库为通用资产（公开资料提炼的规律与句式），不含你的任何信息。
- 删除个人数据：删除 `users\<用户名>\` 目录即可。
