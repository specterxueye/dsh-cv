# 简历大师 · 用户手册

> 对应版本：dsh-cv v1.0 · 配套文档：[README](../README.md)

本手册面向最终用户（求职者），按完整使用流程说明操作步骤。插件适用于中文求职场景，支持技术开发岗、央国企等方向的定制简历。

---

## 1. 准备工作

| 项目 | 说明 |
|------|------|
| 运行环境 | DeepSeek Harness（DSH），已挂载 `resume-writing` 技能（见 README「安装」） |
| Node.js | ≥ 16（用于生成器/校验器脚本） |
| magicv.art 账号 | 用于简历渲染与导出（https://magicv.art） |

聊天方式触发：说出「帮我写简历」「分析这个 JD」「生成 magicv JSON」等即可自动加载技能。

---

## 2. 建立人物档案（第一次使用必做）

档案是之后所有简历的事实来源，只需建一次，可跨会话复用、跨岗位使用。

### 2.1 提供信息

按提示分步回答（每轮 3 个问题以内），覆盖：

1. **基本信息**：姓名、出生年月、所在城市、联系方式、政治面貌（投央国企必填）
2. **教育经历**：学校、专业、学位、起止时间、GPA/排名、主干课程、荣誉
3. **实习/工作经历**：公司、职位、时间、角色（你是否主导）、具体负责事项、量化产出（如「覆盖 20+ 页面」「127 条开发记录」）
4. **项目经历**：名称、级别（国家级/省级/校级）、角色、时间、技术栈或方法、成果指标
5. **校园经历、证书奖项、技能、自我定位**

也可以直接粘贴已有简历文本，或提供材料目录路径（插件会反解析）。

### 2.2 产出

- `users\<用户名>\<名字>-事实基线.json`：全部事实 + 来源。**每条事实必须能溯源到你提供的信息或材料文件**；无法确认的会标注「待确认」。
- `users\<用户名>\<名字>-画像.md`：卖点（3-5 个）、定位语、可迁移技能、避雷点（内部参考，不进入简历正文）。

> 注意：**待确认的事实不会写入简历**。如果你希望某条信息使用，先提供来源。

---

## 3. 提供招聘要求（JD）

- **文字 JD**：直接粘贴全文。
- **图片 JD**：提供图片路径；插件自动识别分析。识别后**会列出不确定项请你确认**，不会静默猜测。

插件输出《JD 理解卡》：

| 栏目 | 内容 |
|------|------|
| 硬性要求 | 学历、年限、技术栈等必备条件 |
| 软性要求 | 沟通、协作、抗压等 |
| 加分项 | 证书、项目、爱好等 |
| 关键词表 | 简历中将命中的岗位词 |
| 缺口清单 | ★ 要求具备但你材料中没有的能力——如实列出，并给出处理策略 |
| 公司风格 | 央国企 / 互联网 / 外企 / 初创（影响措辞与版式） |

**缺口的诚实处理策略**（不会编造）：挖掘相近经历 / 建议补充材料 / 明确不写。

---

## 4. 生成定制简历

### 4.1 写作策略（生成前先看，可要求调整）

插件会先输出写作策略供你审阅：

- 经历排序与详略（按岗位相关性）
- 关键词放置与加粗计划
- 技能分层（第一/二/三梯队）
- 自我评价 3 条（结论+论证）
- 缺口处理
- 一页裁剪清单

确认或提出修改后进入生成。

### 4.2 生成与校验

```powershell
node "scripts\build-resume.mjs" --profile <事实基线.json> --strategy <写作策略.json> [--out <输出.json>]
node "scripts\validate-resume.mjs" <输出.json> [--strict]
```

校验器检查：必填字段、菜单-数据键一致、HTML 结构、UUID、`autoOnePage`、内容真实性标记。**校验不通过不交付。**

### 4.3 交付物

- 简历 JSON（magicv 格式，文件名：`<姓名>-<岗位>-<学校>.json`）
- 《写作说明》：关键词命中、来源说明、缺口清单、优化清单自检结果（✅/⚠️/❌ + 原因）

---

## 5. 导入 magicv.art

1. 打开 https://magicv.art/app/dashboard/resumes
2. 导入/新建 → 选择生成的 JSON 文件
3. 选择模板渲染（`templateId: classic`，`autoOnePage` 已开启）
4. 微调细节后导出 PDF / 图片

**一页验收**：渲染后高度应 ≤ 1123px（可运行 `scripts\render-height.mjs` 测量）；如超页，回插件按「裁剪清单」迭代。

---

## 6. 迭代与诊断

- 修改 → 再校验 → 再测量，**直到优化清单全绿**（或明确知道哪条做不到、原因是什么）。
- 人工微调后可在对话中请插件「以此版本为基线继续优化」。
- 新发现的事实会在下次建档时回填事实基线（保持多份简历事实一致）。

---

## 7. 多岗位版本

一份档案可产出多份岗位定制简历，互不覆盖：

- 每份写入 `users\<用户名>\output\`，文件名含岗位方向
- 切换岗位可对照《分岗位规则》：技术岗强调项目深度与技术栈；央国企强调稳定性/荣誉/政治面貌与真实政务项目；数据可视化岗前置 ECharts/交通局项目等
- 版本差异说明随写作说明交付

## 8. 常见问题

**Q1：图片 JD 识别不出来怎么办？**
插件会列出不确定项；如仍无法识别，直接粘贴文字即可。识别依赖视觉桥可用性（DSH 环境）。

**Q2：简历写不满一页 / 超过一页？**
策略中会有裁剪清单（按岗位相关性删减）与密度建议（目标 0.9–1.0 页满载）。超页优先精炼措辞，不删真实数据；不足一页说明信息量不足，建议补充真实材料。

**Q3：某岗位要求的能力我没有，会怎么写？**
如实进入缺口清单：挖掘相近经历 / 建议补充材料 / 明确不写。插件不会编造或粉饰（真实性铁律）。

**Q4：简历里的数字是编的吗？**
不会。每个数字可溯源到事实基线的来源；无据不写。

**Q5：换电脑 / 换目录怎么用？**
clone 后运行 `pwsh -NoProfile -File scripts\install.ps1` 即可（自动设置路径、建立技能联接、渲染注册壳），无需手工修改任何路径。

**Q6：我的个人数据会被上传到仓库吗？**
不会。个人数据仅存本机 `users\<用户名>\`，仓库 `.gitignore` 已排除。

---

## 9. 数据与隐私

- 你的事实基线、画像、简历成品只保存在本机 `users\<用户名>\` 目录。
- 写作规律库为通用资产（公开资料提炼的规律与句式），不含你的任何信息。
- 删除个人数据：删除 `users\<用户名>\` 目录即可。
