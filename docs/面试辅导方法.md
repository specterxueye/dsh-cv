# 面试辅导方法（概念教学 · 讲透而不是背答案）

> 本文是 dsh-cv 的**面试侧方法论**，与 `preset\skills\interview-pitch`（项目讲稿）、`preset\skills\mock-interview`（模拟面试）配套使用。
> 解决的问题：候选人常见的失败不是"没准备"，而是**背了答案但被追问两层就崩**——因为概念是记的，不是懂的。

---

## 一、核心原则

1. **先认东西，再讲概念**：如果文档里出现"用某工具处理某文件"而候选人不知道那个工具/文件是什么，后面全是死记。所以**每个第一次出现的名词都要就地解释**：它是什么 → 长什么样/怎么操作 → 解决什么问题 → 在这个项目里在哪。
2. **先机制，后结论**：不写"mAP 越高越好"，而写"mAP 怎么算出来的、为什么这个阈值下会低"。
3. **每个概念都要落到候选人的项目**：给出该概念在**他自己的项目**里的具体数值与出处文件（没有具体值的，明确标"未实测/引用数据"，绝不编）。
4. **建立框架，而不是线性罗列**：先给一张"全流程数据流图"（每步的输入/输出/产物文件），再把概念挂到流程的对应位置上。
5. **语气校准（correspondence with reality）**：候选人的表述必须与真实贡献对齐——**能独立做的写"熟悉/独立完成"，能看懂、能配合、做过一次的写"了解"**；AI 辅助完成的部分主动说明，不揽功。

---

## 二、文档结构（三层）

### 第 0 层：前置篇 —— 认全工具、文件与最小原理

| 内容 | 写法要求 |
|---|---|
| 软件与工具 | 每个工具：是什么（软件/库/命令/服务）· 界面或用法 · 解决什么问题 · 在本项目哪个环节 |
| 文件与格式 | 目录结构、文件命名规则、关键文件**逐字段/逐列**解释（例如配置文件的每个键、数据文件的每一列） |
| 最小必要原理 | 用一个流程图讲清"这件事到底在干什么"，然后把行话（超参、损失、指标）挂回流程的每一步 |
| 名词索引 | 全篇名词 → 一句话 → 指向详解章节，方便回查 |

### 第 1 层：概念精讲 —— 每个概念四层（**不再使用生活类比**）

```
① 它到底是什么（机制）
   · 定义 / 公式 / 数据从哪一步产生
   · 各量之间怎么互相影响（例如阈值升高会让哪个指标升、哪个降）

② 在实际开发流程里怎么用
   · 出现在流水线的哪一步、产物是什么文件
   · 怎么读它、拿它做什么决定（判断收敛 / 判断过拟合 / 定位问题 / 调参）

③ 在你的项目里是什么
   · 具体数值 + 出处文件（没有就写"未实测"）
   · 这个数值说明什么、正常范围是什么

④ 面试口语版 + 容易搞错的地方
   · 2-3 句能直接说出口的口语版
   · 常见错误说法（把 A 说成 B、报未经核实的数字、把工具的默认行为说成自己做的）
```

### 第 2 层：诊断与压力测试

- 每天挑 2 个概念，候选人**用大白话复述**，必须包含三件事：**机制 / 我项目里的数值与出处 / 我用它做过或会做什么决定**。
- 辅导者挑三类错误：① 术语解释术语 ② 只报数值不知含义 ③ 说了做不到的事（把引用数据说成实测、把默认配置说成自己设计）。
- 用 `mock-interview` 技能做**两层追问**验证：事实层（这个数字怎么来的）→ 判断层（为什么这么选、还有什么方案）。

## 三、反模式清单（写与讲都要避免）

| 反模式 | 例子 | 为什么不行 | 改法 |
|---|---|---|---|
| AI 总结腔 | 把做法抽象成带引号的口号：`以"按期上线"为交付标准` | 不像人话，像总结 | 写具体动作与结果 |
| 自我评价式习惯描述 | `习惯先用测试与备份机制定住质量底线` | 说的是"我的习惯"，不是"我做过什么" | 写"做了 A、B，验证了 C" |
| 模糊量词 | `独立完成过完整桌面客户端` | "完整/过"无信息量，且易被追问倒 | 写清规模、范围、你负责的环节 |
| 无锚点软标签 | `学习能力强`、`抗压能力强` | 无论证 = 无信息 | 换成证据或删除 |
| 术语解释术语 | 用"召回率"解释"漏报" | 没离开行话 | 先用业务语言说清，再给术语名 |
| 引用数据当实测 | 把论文里的对比数据说成自己跑的 | 诚信风险，一追就穿 | 主动标注"引用/课程化数据" |
| 生活类比代替机制 | 通篇打比方 | 记住比方但答不出机制，追问即崩 | 类比可以出现一次帮助记忆，但机制必须写清 |

## 四、与技能的配合

| 环节 | 用什么 | 产出 |
|---|---|---|
| 项目讲稿 | `interview-pitch` 技能 | 按岗位角度的口述稿（90-120 秒）+ 2-3 条可能追问 |
| 模拟面试 | `mock-interview` 技能 | 双模式（友好复盘 / 高压追问）× 三类型（BQ / JD 面 / 混合）+ 复盘含"最弱回答的改善版" |
| 概念教学 | 本方法 | 前置篇 + 概念精讲（四层格式）+ 每日自检闭环 |
| 事实兜底 | `scripts\audit-facts.mjs` | 讲稿与答案里的数字同样要能在事实基线里找到出处 |

> 建议顺序：**先概念精讲（懂）→ 再讲稿（能讲）→ 再模拟面试（扛得住追问）**。跳过第一步直接背讲稿，是最常见的失败路径。
