# dsh-cv 公开发布优化计划

更新日期：2026-10-18。状态：用户已授权分批实施；本页的审查发现保留原始代码基准，当前进度见执行记录。

本计划面向公开发布的 **DeepSeek Harness 求职插件**。当前项目有可用价值，但现有宿主接入、校验和渲染检查不足以支撑其对外宣称的保证。推荐先修复正确性与接入，再改善首次使用和分发；保留现有规则、技能和零依赖 CLI，不必另建 Agent 框架、数据库或完整简历编辑器。

## 审查基准与范围

审查代码基准为 `557d95e8584dd3f2fda695a0255f0b8af5992227`，仓库声明版本 `0.5.0`。审查开始时工作树干净，本地 main 与在线 main 的提交一致。

- 覆盖 76 个被 Git 跟踪文件所组成的产品与技术边界：13 个 JS 脚本、2 个 PowerShell 脚本、48 份 Markdown，以及配置、模板、锁文件等。重点逐项检查了生成、校验、授权、合并、安装、技能与文档合同。
- 额外静态检查 2 个本地未跟踪的个案脚本，它们不属于公开仓库，不能据此认定公开仓库泄露个人资料。
- 排除 `users/`、`test/`、`output/`、`scripts/.smoke/` 中的实际个人内容，以及 `node_modules` 中与宿主基准无关的第三方实现。锁文件只检查关键依赖与运行要求。
- 本机实证基准为 `@deepseek-ai/dsh@0.2.0-rc.1`、Node `v24.21.0`、PowerShell `7.6.5`。同时核对当前 DSH 官方分发与预设文档，不能把浮动 master 当作稳定兼容承诺。
- 现有仓库自检为 27 项通过、0 项失败；两份安装脚本 PowerShell AST 语法错误为 0。
- 对脚本执行了 23 个独立内存合成用例，另有模板用例重复确认一次。文件读写和浏览器依赖被替换为内存对象，没有写出业务稿、打开真实网站或上传简历。主审另独立复核了授权门和数字匹配反例。
- 读取在线 GitHub 的仓库、分支、标签、Release、Ruleset、PR 和 Actions 信息；检查本地 9 个可达提交、忽略规则、历史文件路径、对象完整性和常见密钥特征。常见密钥特征未命中，不等于全面证明历史不含敏感信息。

证据分为：**已证实**（当前源码、配置、API 或合成执行结果）、**推断**（由证据推导的使用影响）、**待验收**（真实 DSH 会话、真实 MagicV/PDF、跨机安装与陌生用户操作）。下文的优先级是发布顺序，不是对已发生事故的认定。

主要取证工具包括 `rg`、`git status --short`、`git log --all`、`git ls-files`、`git check-ignore`、`git fsck --full --no-reflogs`、`git diff --check`、`node scripts/check.mjs`、Node VM 内存合成执行、PowerShell AST，以及 GitHub Connector 的只读 GET。外部版本和机制通过下文列出的官方文档与 Release 核对；没有运行真实安装来代替审查。

## 产品定位

用户已确认的目标是公开 DSH 插件。推荐的聚焦定位为：**在 DSH 内，把用户确认的经历整理成可追溯、可按岗位定制、保留修改记录的中文简历，并可衔接面试准备。**

现有资产较适合先服务校招技术岗、央国企求职者；这是建议，尚不是已确认的范围收缩。有经验、科研、多页需求应通过政策入口或明确的支持边界处理，不能静默套用校招规则。

项目的差异应落在事实整理、职责边界、定向改写和变更保护。Magic Resume 已提供编辑、预览、PDF 导出等能力；Resume Matcher 也已有定向简历产品能力，继续堆通用编辑器功能的收益低于让现有承诺可信。[Magic Resume](https://github.com/JOYCEQL/magic-resume)、[Resume Matcher](https://github.com/srbhr/Resume-Matcher)

应保留的基础：通用资产与个人内容分层、生成与校验可独立使用、明确批准门、真实渲染意识、按需读取岗位语料，以及承认已知限制的文档。公开产品不应承诺自动证明真实性、通过 ATS 或提升录用率。

### 推荐的最小治理

1. **受保护 main 和短期分支。** 代码修复走 `codex/<主题>` 或其他短期分支，PR 满足必需 CI 后合并；禁止 force push、删除主分支。单人项目不要求必须由第二人批准，不需要 Gitflow 和常驻 develop。
2. **CI 从文件自检升级为行为门槛。** 保留快速 check；新增纯合成的生成→结构→授权→数字扫描→内容保真回归，以及隔离 profile 原生安装与诊断。渲染算法离线测，在线站点烟测独立运行并核对导入身份。
3. **合成测试与个人隐私分离。** 不要取消现有 `test/` 忽略后把真实资料提交；可以新设可跟踪的 `tests/fixtures`，只放明确虚构资料。不要用真人稿做 CI 输入。
4. **版本向前推进。** 不删除、移动或重写旧标签。为历史 v1.0.0 Release 说明旧渠道状态；新适配版使用高于已有公开版本的版本线，例如先发 `v1.1.0-beta.1`。若实际破坏已发布公共契约，则使用新的主版本，定版时按兼容性裁决。测试版与稳定版的 Latest 指向分开管理。
5. **发布源自验证过的提交。** 版本、tag、CHANGELOG、Release、宿主兼容范围和安装命令一致；包内资源使用 files 白名单，检查打包清单，版本包包含完整规则、技能引用与脚本。
6. **恢复依赖可审查性。** `package-lock.json` 当前被 `.gitattributes` 的 `-diff` 隐藏文本差异；保留 generated 统计标记即可，允许审查依赖变化。补 `.env*` 和凭据类本地文件的忽略规则与提交前扫描；当前没有发现这类泄漏，属于缺少预防措施。
7. **轻量维护入口。** 补用途说明、dsh-plugin topic、简短安装演示、Issue/PR 模板、贡献与安全反馈说明，以及每次发布的验收清单。MIT 与第三方声明已有基础，应保留。

`package.json` 的 `private:true` 对 GitHub 分发不是错误；只有选择 npm 发布时才需要调整。没有 commit 签名、没有第二名 reviewer、只有一个主分支，也不应被直接判为不规范。

## 推荐架构

推荐保留一个仓库，分清三类责任即可：

主调用关系为：DSH 原生 bundle → 技能与规则资源 → 可独立 CLI → 正文与 MagicV 输出 → 独立验收。用户资料从稳定的数据目录读取，与包内资源分开保存。

- **接入层**：原生配置包提供技能资源，默认复用标准预设的工具；独立人设与完整预设可选。唯一 provider 名称避免注册冲突，包相对资源解析取代机器级环境依赖。
- **用户资料层**：资源包只读；用户选择稳定的数据目录，单独保存事实、来源、偏好、稿件和批准记录。原生安装进入 node_modules 后不得把 users 放在包内。兼容旧目录并提供显式迁移说明，未经批准不自动搬个人数据。
- **业务层**：先用 JSON 文件和明确 schemaVersion。对高风险事实记录稳定 factId、来源、确认状态、对象、单位、时间和职责归属；不要求每次从全部 Markdown 重建事实。用户口头确认可作为一种来源，材料核验强度单独标记。
- **校验层**：结构检查、授权范围、来源命中、待核事实和排版分别报告。批准应针对具体基稿与方案，不能靠一个永久 approved 布尔值代表所有后续内容。
- **输出层**：MagicV 是适配目标，正文同时可读、可复制；先保证现有出口保真，不立即接入多种编辑器。外部格式和 DOM 变化通过合成夹具与兼容烟测发现。

复杂度优化只做三件事：用原生安装替代手工注册；合并重复的浏览器启动、导入和结果处理；把重复流程规则收敛到一份权威流程与按需 policy。旧脚本退出使用后再按授权单独处理删除，不预报未经实际测量的删行收益。
