## 4. 便利性实测结论：方便快捷吗？

**结论：对"已装 DSH 的 Windows 用户"＝ 3 条命令 + 一次对话即可产出可用简历；对非 Windows 用户仍不便。**

好的部分：

- 安装 3 条命令、**不需要管理员权限**、幂等，且装完自动自检（环境变量 / 技能联接 4/4 / 注册壳）；
- 使用全在对话里，无需记命令；文档分三层（安装与使用 → 用户手册 → 架构评估）；
- 建档交互成本被 `cv-intake` 显著降低：从"写一整段经历"降到"回 `1✅ 2改成 X`"。

本次消除 / 仍存在的卡点：

| 卡点 | 性质 | 处置 |
|---|---|---|
| 渲染脚本硬编码 `C:\Program Files\...\chrome.exe`（4 处） | **别人 clone 必挂** | ✅ 本次参数化：`--chrome` > `$DSH_CV_CHROME` > `$CHROME_PATH` > 平台探测 > playwright `channel:"chrome"` |
| 真实渲染要 `playwright-core`，但文档只说"设置 `PLAYWRIGHT_DIR`"，没说怎么装 | 隐形坑，用户会卡死 | ✅ 本次补 `npm i -D playwright-core` + `package.json` devDependency + 解析顺序（cwd/env/直接 require） |
| `e2e-render.cjs` 用旧判据（容器高 1750px）却顶着"一页验收"名号 | 判据错位，可能给出假通过 | ✅ 本次标注为旧判据并指向 `render-measure3.cjs` |
| 导入 magicv.art 必须手动 | 产品边界（magicv 无公开 API） | ➖ 保持；手册给步骤，`e2e-render.cjs` 可代跑 |
| 非 Windows 无安装脚本 | **最大剩余便利性缺口** | ⏳ 见 §2 第 1 条 |

## 5. 本次实测发现的真问题（待裁决）

用统一后的口径实跑本机蓝本 `users\王琦皓\output\蓝本-AI应用开发.json`：

```
render-measure3.cjs → 分页标记「第1页结束」y = 1073.6px（与文档记载一致，且**只有这一处标记**）
                      最后一行文字底 y = 1115.3px  →  ❌ 溢出标记线 42px
render-blocks.cjs  → 自我评价块 y=971.9 h=150.5 → 内容底 ≈ 1122.4px（A4 纸高 1123）
```

**含义**：这份"已验证蓝本"在**纸高**上是一页（≤1123px），但内容侵入了**下页边距区**（超过标记线 42px）。

两种判据给出相反结论：

- `02-workflow.md` 阶段 5b 的五条判据（预览零溢出 / 无第 2 页标记 / 无"内容较多"警告）→ **通过**；
- `render-measure3.cjs` 的"末行须在标记线之上" → **不通过（溢出 42px）**。

**待你裁决（三选一）**：

1. **判据取严**（标记线为准）→ 该蓝本需再精简约 42px；好处是 PDF 导出绝不会切到内容；
2. **判据取纸边**（≤1123px 即算一页）→ 该蓝本合格，但需接受内容贴到下页边距；
3. **两级并列**：纸边 1123px 为**硬门槛**，"越过标记线"降级为 **WARN**。
