# 安装与使用

当前目标兼容范围：DeepSeek Harness `0.2.0-rc.1`，Node 22.3+ 或 24.x。本机实测 Node 24，Node 22 与其他系统待 CI。其他 DSH 版本需重新验证，不能用忽略版本风险代替验收。

## 原生安装

保留 DSH 标准预设，插件只提供四个技能和本地资源，不接管宿主的工具与模型配置。安装到你实际使用的 profile；下例为 web，桌面托管 profile 应使用桌面端的插件管理入口。

```powershell
# 从当前资源包目录安装；路径含空格、中文或单引号都作为独立参数传递
pwsh -NoProfile -File ./scripts/install.ps1 -Profile web
# 原生命令等价形式
# dsh plugin --profile web add "<插件目录或发布的tgz文件>"
```

不需要设置 DSH_CV_ROOT，不写注册表、不创建全局技能联接、不生成 .agent-presets 注册壳。安装器的 `-DryRun` 只展示目标与命令。原生命令非零时安装器也失败；命令成功表示依赖注册完成，技能在会话中可加载仍需另行验收。

重开对应 profile 的会话，确认 cv-intake、resume-writing、interview-pitch、mock-interview 可加载。向其提出「帮我整理已有简历」，检查技能能从 resourceBase.path 定位自己的规则。未执行真实对话的安装不能报告为完整验收。

## 数据目录与迁移

为每位用户明确选择一个稳定目录，例如 D 盘的个人求职目录。规则和脚本从插件包读取，个人资料不写在 node_modules 或包资源内。生成器默认把成品写到事实基线同级的 output；也可以用 --out 指定文件，默认不覆盖已有稿。

```powershell
node "<资源根>/scripts/paths.mjs" --data-dir "<个人求职目录>"
node "<资源根>/scripts/build-resume.mjs" --profile "<个人目录>/事实基线.json" --strategy "<个人目录>/策略.json"
```

旧仓库 users 目录可以继续作为显式数据来源，不自动移动、重命名或改写。迁移时先由用户选择新目录、复制并比对文件，再切换路径；原件保留作为恢复点。卸载插件不会删除这些资料。

如果旧版在 DSH_HOME/skills 下留下同名技能，安装器会报告冲突并停止。先核验每项到底指向本插件、旧版本还是其他来源；仅停用经核验属于旧版的入口，并保留原目标和恢复说明。不要按目录名或路径子串批量删除。旧注册壳不再被本安装器维护，未经授权不自动清理。

## 更新与移除

更新使用原生管理器重新 add 新版本的目录或 tgz，随后重开会话并验证技能资源来自当前包。发布包有显式资源清单，不包含用户资料、测试输出、node_modules 和本机个案脚本。

```powershell
dsh plugin --profile web remove dsh-cv
```

依赖移除成功后，重新打开会话确认该 provider 不再提供四个技能。回退时 add 保留的旧 tgz 或目录即可；个人数据保持原位。若同时安装了其他来源的同名技能，它们仍可能存在，应按来源判断。

## 隐私与外部编辑器

文件默认保存到用户选定的本地目录；仓库忽略规则只是防止误提交的一层保护，不能代替发布包检查。发给 DSH 的材料会由你所配置的模型处理。MagicV 是可选外部出口，在线测量命令会导入所选 JSON；运行前确认允许处理该份资料。项目不承诺端到端离线，也未核验第三方服务的保留政策。
