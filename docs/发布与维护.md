## Git 与分支

保留单一 main 和短期工作分支，通过 PR 合入。每批修复独立提交，提交前检查 diff 和合成回归；个人事实、成品、凭据和个案脚本不得暂存。无需增加 develop、Gitflow 或多人审批制度。

回退代码使用单独的 revert 提交；恢复旧安装使用原生 plugin add 指向保留的旧包。个人数据目录不在包管理生命周期内，不因回退代码而搬动、覆盖或还原。

## 候选包与版本

本次安装方式、批准 schema 和默认输出位置有不兼容变化，采用新的主版本 `2.0.0-beta.1`，不继续倒退的 0.x 标签序列。beta 不是稳定兼容承诺；这是基于合同变化的版本决策，参照 [SemVer](https://semver.org/)。

```powershell
npm ci --ignore-scripts
npm test
npm run check
npm run test:browser
npm run check:package
# 在个人资料以外的临时目录准备固定宿主后设置 DSH_TEST_CLI：
npm run test:dsh
New-Item -ItemType Directory -Force .test-runs/release | Out-Null
npm pack --ignore-scripts --pack-destination .test-runs/release
Get-FileHash .test-runs/release/dsh-cv-2.0.0-beta.1.tgz -Algorithm SHA256
```

package.files 逐文件列出资源，新增文件必须显式登记。打包检查核对 npm 实际清单与允许清单完全一致，回归额外放入合成私人文件验证排除。包不包含测试、依赖、真实档案、本地输出或历史独立预设壳。不要直接打包整个工作目录。

候选包可以通过 `dsh plugin --profile <目标profile> add <tgz绝对路径>` 安装；卸载与目录包相同。发布前对实际 tgz 再跑原生生命周期，登记版本、提交、文件数和校验和。package 的 private:true 防止误发 npm，不影响 GitHub tgz 分发。

## 正式预发布之前

- 每个发布候选提交的线上 CI 全部通过；首次已完成，原生安装组合仍按上述实际范围登记。
- 用合成材料完成一次真实 DSH 求职对话，确认首次创建、已有稿修改、待核事实与批准分支。
- 外部 MagicV 的实际导入、目标稿件核对和导出 PDF 均通过；受登录或网站变化阻挡时登记限制，不沿用离线页数结论。
- 至少邀请 3 位陌生用户完成首份任务，记录是否独立安装成功、首次可用交付耗时、事实纠错与额外人工步骤。先确认他们愿意提供反馈，不上传或收集简历原文。
- 维护者审阅 tgz 与发布说明后，另行批准 tag 和 GitHub pre-release。不得自动标为稳定 Latest，也不承诺 ATS 或录用效果。

当前仍有验收缺项时，可以本地试用和审阅候选包，不能将其称为已完成公开发布。
