# 建档 frontier 问题树（温和档 · 默认 7 轮）

> 用法：**整轮问完再停**，每题带推荐答案／选项，允许"跳过/没有"。带 🔍 的项**先派 subagent 自查**，不占用户；带 ✍️ 的是"只有用户知道、必须问"。
> 落盘字段对照 `profile\profile-template.json`。凡无材料佐证的一律记 `status: "pending"`。

## R0 · 材料入口（先于一切，1 问）

```
❓ **Q0** - **手上有什么现成材料？**：已有简历（PDF/Word/图片）、成绩单、证书原件、实习单位材料、个人项目仓库地址、课程设计报告——有哪个给哪个，你少答很多轮。

➡️ 推荐：先给一份现有简历（哪怕很旧），我按它反解析后再逐轮找你确认，效率最高。
```

- 🔍 拿到路径/仓库后**派 subagent**解析：抽字段 + 记来源；抽到的事实直接进基线 `source`。
- 反解析结果**必须逐条回显给用户确认**，不得静默采信（旧简历里常有夸大或过期信息）。

## R1 · 基本信息（✍️ 6 问）

| # | 问题 | 推荐答案 / 选项 |
|---|---|---|
| Q1 | 姓名、称呼 | — |
| Q2 | 出生年月、籍贯 | — |
| Q3 | 手机、邮箱 | — |
| Q4 | 现居城市 / 意向工作城市 | 选项：本地／一线／不限 |
| Q5 | 政治面貌 | 选项：中共党员／预备党员／共青团员／群众（**投央国企必填**） |
| Q6 | 证件照 | 选项：有（给路径）／暂不提供（版式先留位） |

> 落盘：`basic.*`。`employementStatus` 默认"在校"，社会招聘改"在职/离职"。
> 隐私：手机号只进本机基线，不进写作说明正文（`data\rules\00-总则.md`）。

## R2 · 教育（✍️ 4 问 + 🔍 2 项）

| # | 问题 | 推荐答案 / 选项 |
|---|---|---|
| Q1 | 学校、专业、学历、起止时间 | 全称，对照学信网 |
| Q2 | GPA / 排名（专业排名或百分位） | 选项：都有／只有 GPA／都没有（**无则整段省略，不写"成绩良好"**） |
| Q3 | 主干/核心课程（列 5-8 门） | 按**目标岗位相关性**推荐保留哪些，其余裁掉 |
| Q4 | 在校荣誉（奖学金、竞赛、荣誉称号） | 选项：国家级／省级／校级／无；**带年份** |

- 🔍 成绩单在手 → 派 subagent 核对 GPA 与排名口径（避免"绩点 3.6"与"排名 30%"互相打架）。
- ✍️ 预科/专升本/转专业等特殊学制：**先问清楚**，涉及时间线自洽判断（阶段 5c 第 1 条）。

## R3 · 实习 / 工作（✍️ 5 问 + 🔍 1 项）

| # | 问题 | 推荐答案 / 选项 |
|---|---|---|
| Q1 | 公司全称、职位、起止时间 | — |
| Q2 | 你的角色与责权 | 选项：组长/负责人／核心开发／模块负责人／参与者（**别默认"参与"**） |
| Q3 | 项目性质背景 | 选项：真实商业项目／中标项目／校企合作／外包／内部工具 |
| Q4 | 你具体做了什么（列 3-6 件事） | 给句式钩子："我做了 X，覆盖 Y，结果是 Z" |
| Q5 | 有没有数字（开发记录/接口/页面/团队规模/耗时） | 选项：有具体数／只有大概／完全没有；**大概数记 pending** |

- 🔍 单位材料/实习报告在手 → 派 subagent 抽数字，供 `audit-facts.mjs` 溯源。
- ✍️ 保密项目：问清**能说什么、不能说什么**，写进画像的避雷点。

## R4 · 项目经历（✍️ 6 问 + 🔍 按仓库数）

| # | 问题 | 推荐答案 / 选项 |
|---|---|---|
| Q1 | 项目清单（有几个报几个，先求全） | 明说"这一步可以多报，后面练 JD 时再挑" |
| Q2 | 每个项目的名称 | — |
| Q3 | 项目级别 | 选项：真实项目／课程设计／课程实验／竞赛／大作业（**不许含糊成"项目"**） |
| Q4 | 你的角色 | 选项：独立完成／前端／后端／算法／统筹 |
| Q5 | 技术栈或方法 | 一句话，版本号可选 |
| Q6 | 成果指标 | 数据规模／准确率／功能点数／文档数；课设类写"形成可复现基线"也算 |

- 🔍 给了仓库地址 → 派 subagent 查 README、commit 量、依赖、star（**只取可复现的客观数**，不把 star 当成果吹）。
- 落盘：`projects[]`；此池即后续**场景 B 项目取舍**的候选池，同时写入 `项目素材库.md`。

## R5 · 校园经历（✍️ 3 问）

| # | 问题 | 推荐答案 / 选项 |
|---|---|---|
| Q1 | 学生工作 / 社团 / 志愿（组织+角色+时间） | 重写为"实习格式"：做了什么 → 量化 → 保障了什么 |
| Q2 | 具体产出数字 | 活动场次／人数／推文篇数／视频条数／持续时间 |
| Q3 | 是否有用户明确不想写的经历 | 选项：社会实践／其他（**明确排除项永不显示**） |

> 注意：实验室/科研经历**归实习或项目**，不混进校园（阶段 5c 第 3 条）。

## R7 · 定位、口径与排除项（✍️ 5 问，收口轮）

| # | 问题 | 推荐答案 / 选项 |
|---|---|---|
| Q1 | 目标岗位方向 | 选项：AI 应用/Agent／后端／前端／算法／测试／央国企综合 |
| Q2 | 你的三个卖点（自己说） | 给候选："工程完整度／交付速度／真实项目主导度" |
| Q3 | 最想让 HR 记住的一句话 | 后补进画像"定位语" |
| Q4 | 哪些点经不起深挖（**内部避雷点**） | 说明：只进画像，**永不进简历** |
| Q5 | 还有什么"跳过了但想补"的 | 生成"建档后补"清单，不硬拖本轮 |

## 收口判据

1. R1-R7 的 ✍️ 问题都已得到答复或明确标注"跳过/没有"；
2. 所有数字有来源，或已标 `status: "pending"`；
3. 用户对基线内容**明确确认**（"可以/没问题"），而非沉默；
4. 写盘：`users\<用户名>\<名字>-事实基线.json` + `<名字>-画像.md` + `项目素材库.md`；
5. 回 `resume-writing` 阶段 2（要 JD），**不要**跳到生成。
