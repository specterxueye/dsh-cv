# 项目取舍参考

以真实候选经历为池，用户明确排除的项目不进入。可以包括旧稿隐藏项目，隐藏不等于删除。排序用于解释判断，不是招聘平台评分或录用预测。

| 维度 | 需要说明的证据 |
|---|---|
| JD 相关性 | 对应 JD 的实际职责或技术需求 |
| 任务相似度 | 用户确实做过的场景与目标工作有什么共性 |
| 级别真实性 | 课程、实验、竞赛、研究或真实业务按实际性质填写 |
| 个人贡献清晰度 | 具体负责/协助了什么；不以主导身份压过相关的真实协作贡献 |
| 结果可说明性 | 已确认的定性/定量结果及来源；未知不自动判不会 |
| 区分度与篇幅 | 该经历新增什么有价值的信息，适合当前页数政策吗 |

给出建议展示/备选/隐藏及各自依据；项目数量由材料与用户 policy 决定，不固定三四项，也不为凑数量弱化真实经历或编项目。可以用明确标为经验判断的分值辅助讨论，不把分值当客观招聘结论。

与改写范围、栏目和页数放在同一方案卡里集中批准。用户仅选择项目不自动授权所有文本变化；已明确批准整份方案后不重复拆分索批。输出 projectVisibility、理由及 touchedFields，绑定本次基稿与策略；流程见 [权威工作流](../../../prompts/02-workflow.md)。
