# 建档与项目取舍

把已有材料整理成事实摘要，按当前目标补必要缺口。完整流程见 [权威工作流](../../prompts/02-workflow.md)。

路径：从宿主给出的 resourceBase.path 向上三级定位资源根，脚本使用绝对路径；事实和个案记录只放用户明确选择的个人目录。不依赖 DSH_CV_ROOT，不写公共资源。

1. 已有简历/材料先读摘要，集中核对冲突、估计数字与职责边界；不要重问材料中的学校、日期和项目。材料读取范围须获得授权。
2. 没有材料时，按当前最有价值的一小组问题推进，可跳过或待补。题库是备用，不是七轮必经流程。推荐答案只用于策略取舍，个人史实不给虚构默认答案，也不能把未回复当确认。
3. 用户确认与材料强度分开。已明确确认的定性职责可用，估计数字继续 pending。没有材料不等于没做过，简历未写不等于不会。
4. 项目按相关性、本人贡献与可说明的结果排序，数量随 policy，不固定三四项。与改写范围、页数和栏目合并成一张方案卡确认，不重复索批。
5. 不由 JD 或角色补细节：只确认协助测试时，测试对象、方法与产出仍待材料确认，不能补成接口测试或测试报告。

新事实使用 value/status/source；材料强度单列。待核事项保留在 pendingFacts，不进入生成或来源集合。公共规则只读，项目隐藏不等于删除。独立材料可在工具可用时委派，否则顺序处理。

按需参考 [建档题库](references/frontier-建档问题树.md) 与 [项目取舍](references/jd-project-fit.md)。事实足够支持当前任务即可进入方案，不要求问完所有题。
