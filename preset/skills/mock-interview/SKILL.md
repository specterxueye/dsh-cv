# 模拟面试（Mock Interview）

不是聊天，是**有规则的面试**：出题有来源、追问有链条、复盘有依据。

> **路径约定**：仓库根 = `$env:DSH_CV_ROOT`。相对路径以仓库根为基准。

## 1. 纪律（最高优先级）

1. **题目只能从事实源里长出来**：出题依据 = `users\<用户名>\<名字>-事实基线.json` + `<名字>-画像.md` + 已验证蓝本 + `output\jd-<公司>-<岗位>.json`（若已做 JD 分析）。**不许问用户根本没做过的事**（问了等于逼人编）。
2. **不替用户编答案**：复盘里的"改善版"只能重写用户**已经说过**的内容（换结构、补 Impact、去掉空话），**不得新增事实或数字**。
3. **一次只问一个问题**，等回答完再继续；禁止一口气抛 5 题（那是问卷，不是面试）。
4. **不评价人品，只评价表达与证据**：反馈落在"逻辑性 / 证据强度 / 与岗位相关性 / 遗漏点"。
5. 用户答不上来时：高压模式**继续追问但给台阶**（"可以从你负责的那部分讲"）；友好模式直接给提示框架。

## 2. 开局（必须先做，不允许直接开始提问）

用 `ask_user_question` 让用户选两个维度（**不要用纯文本问，要给可点选项**）：

- **风格**：`友好复盘型`（问完给反馈，节奏慢，适合梳理思路）／`高压追问型`（连续追问，不给提示，模拟真实压力）
- **类型**：`行为面试 BQ`（项目/协作/挑战/失败）／`岗位匹配 JD 面`（结合目标 JD 出题）／`综合（BQ + JD 混合）`
- 需要的话再问：公司/岗位（若要 JD 面）、时长（默认 6-8 题 ≈ 20 分钟）

## 3. 面试进行

- 出题：从 `references/question-bank.md` 按类型抽，并结合用户真实经历**具体化**（如"你那个 YOLO 项目里…"而不是"讲一个项目"）。
- **高压模式**：对回答中的模糊处按追问链往下挖——`"你说'推动了落地'，具体是怎么推动的？"` → `"这个数字是什么口径测出来的？"` → `"如果重来一次你会改哪一步？"`
- **友好模式**：每题回答后给 3 行反馈：`✅ 亮点` / `⚠️ 缺什么证据` / `🔁 可以这样说`（改写示范）。
- 每题最多追问 2 层，然后换题；记录用户**原话**（复盘要用）。

## 4. 复盘（结束即输出）

```
# 模拟面试复盘 · <公司>-<岗位> · <日期>
- 风格/类型：高压追问型 / 混合 ｜ 题量：N 题

## 亮点（2-3 条）
## 需要加强（2-3 条）——每条附"下次怎么做"
## 最薄弱回答的改善版（1 个，基于你原话重写，不新增事实）
## 暴露出的简历/讲稿问题（若有：口径矛盾、数字讲不清、项目与岗位不匹配→ 回到简历工作流修正）
```

落盘：`users\<用户名>\output\mock-<公司>-<岗位>-<YYYYMMDD>.md`

## 5. 完成判据

- [ ] 开局用可点选项确认了风格与类型
- [ ] 全程一次一问，未连抛问题
- [ ] 每题题目能对应到用户真实经历或 JD 要求
- [ ] 复盘含亮点、待加强、改善版；**改善版未新增任何事实**
- [ ] 若发现简历/讲稿口径冲突，明确指出并建议回到 `resume-writing` / `interview-pitch` 修正
