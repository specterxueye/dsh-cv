# 岗位角度映射 · 追问链 · 危险区

> 本文件是**通用方法论**，不含任何具体用户的数据。用户的真实数字/公司/项目一律从 `users\<用户名>\` 取。

## 一、同一条经历，六种讲法（重心切换）

| 岗位 | ② 背景怎么写 | ③ 重点讲什么 | 术语/证据偏好 |
|---|---|---|---|
| AI 应用 / CV | 数据从哪来、标注与清洗的坑、算力/时间约束 | 数据集构建 → 训练配置与取舍 → 评估方法（为什么看 PR/混淆矩阵而不只看 mAP）→ 部署成可交互应用 | 指标名 + 可复现材料（结果文件、曲线、权重） |
| 前端 / 数据可视化 | 业务方要什么、图表要多快多稳、浏览器/分辨率兼容 | 模块交付节奏 → 图表自适应/全屏/导出等硬骨头 → 接口联调与超时优化 → 与后端/测试的接口约定 | 组件与图表库名 + 覆盖范围 + 交付结果 |
| 后端 / 数据库 | 业务规则多复杂、数据一致性要求 | 实体建模与范式取舍 → 约束/触发器/存储过程把规则落到数据层 → 测试与异常路径 | 库/版本 + 约束设计理由 |
| 算法 / 测试 / 运维 | 质量或效果目标、误判代价 | 方法选择与对比实验 → 边界与异常处理 → 复现与回归手段 | 对比表 + 复现步骤 |
| 央国企 · 综合信息化 | 项目性质（中标/政务/校企）、合规要求 | 规范与流程意识 → 跨组协调 → 文档与验收 → 保密/合规经历 | 流程词（验收/文档/流程）+ 稳定性信号 |
| 产品 / 运营 | 用户痛点、资源约束 | 发现问题 → 定义方案 → 争取资源 → 推动落地 | 用户证据 + 结果指标 + 决策取舍 |

## 二、追问链（面试官顺着你的话往下挖的三层）

**第 1 层 · 事实**："这个数字怎么来的？" → 你要能说出**统计口径与来源**（日志/结果文件/报告）。
**第 2 层 · 判断**："为什么选这个方案？还有别的选择吗？" → 说清**被否掉的方案与代价**。
**第 3 层 · 迁移**："如果规模放大 10 倍 / 数据质量更差 / 工期减半，你会怎么做？" → 考察**方法论是否可迁移**。

常见追问句式（提前准备答案）：
- "你说'主导'，具体你做了哪几件事？团队其他人做什么？"
- "这个指标是在什么数据集/什么条件下测的？样本量多少？"
- "过程中最大的坑是什么？你怎么定位的？现在回头看会怎么改？"
- "这段经历里你最后悔的一个决定是什么？"
- "如果让你重做，时间只有一半，你会砍掉什么？"
- "你说的这个工具/框架，跟另一个比过吗？为什么不用另一个？"

## 三、危险区（口径必须与简历一致，别现场加戏）

| 类型 | 风险 | 正确口径 |
|---|---|---|
| 课程论文/综述里的**引用数据** | 容易被讲成"我实测的" | 明确说"这是论文里引用的对比数据/课程化实验设计，我自己实测的是另一部分" |
| **未公开/私有仓库** | 被问"链接发我看看"就尴尬 | 说"代码在本地/私有仓库，可以现场演示或投屏讲架构"，别说成开源项目 |
| **政治面貌与发展阶段** | 夸大是诚信问题 | 按实际阶段如实说（如"目前是入党积极分子/预备党员，预计某时间转正"），不确定的时间不编 |
| **升学与就业状态** | 口径矛盾会被追问 | 以求职为主线就统一说以就业为导向；不要在不同公司说两套 |
| **亲属任职单位与实践单位重合** | 观感问题 | 按实说，不主动展开；被问再答，强调自己做了什么 |
| **奖项级别** | "省级二等奖"说成"国家级" | 严格按证书原文（赛区/组别/等级） |
| **成绩口径** | 排名/绩点写高 | 与成绩单一致；"前 25%"不能说成"前 20%" |
| **团队角色** | 把团队成果全揽 | 用"我负责的模块是…，团队整体是…"分清边界，反而更可信 |

## 四、时长与节奏

- 90-120 秒 ≈ 中文 200-280 字。**超过 150 秒**面试官会打断，等于白准备。
- ③ 段最多 4 句：面试官靠追问了解深度，不靠你一次说完。
- 每篇讲稿留一个**钩子**（"这块我踩过一个坑，您要听细节我可以展开"）——把追问引到你准备过的地方。
