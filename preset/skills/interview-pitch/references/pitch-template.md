# 讲稿骨架与示例（占位符按真实基线替换，禁止照抄示例内容）

## 一、五段骨架（复制后填写）

```
【项目名】· 目标岗位：<岗位> · 时长：约 <N> 秒

① 开场（1 句）
"<我在 X 项目里负责 Y，把它从 A 做到了 B。>"

② 背景与问题（2-3 句）
"<业务/课程背景；当时的约束：时间/资源/数据/合规；难点是什么。>"

③ 我做了什么（3-4 句，主语=我）
"我先判断了 <取舍点>，因为 <理由>；然后 <动作 1>；接着 <动作 2>；
 遇到 <卡点> 时，我 <怎么定位/怎么解决>。"

④ 结果（1-2 句）
"<量化结果（数字可溯源）>，<这个结果带来了什么/支撑了什么>。"

⑤ 与本岗位的连接（1-2 句）
"这段经历里的 <能力>，正好对应贵司这个岗位的 <JD 要求>。"

可能追问：
Q1: <问题> → 要点：<一句话>
Q2: <问题> → 要点：<一句话>
Q3: <问题> → 要点：<一句话>
```

## 二、五段写法要点（决定讲稿好不好听）

| 段 | 常见错误 | 正确做法 |
|---|---|---|
| ① 开场 | "我介绍一下我的项目…"（废话开场） | 直接给价值+角色，让人立刻知道你在讲什么 |
| ② 背景 | 讲公司/行业大势 | 讲**约束**：时间紧、数据脏、资源少、合规要求——约束才衬得出你的能力 |
| ③ 我做了什么 | "我们团队做了…" | **主语必须是"我"**；讲判断与取舍，讲被否掉的方案 |
| ④ 结果 | 堆一堆数字 | 1-2 个**最有证据**的数字 + 它起的作用（Action-Metric-Impact） |
| ⑤ 连接 | "我学习能力强"（空话） | 点名 JD 里的一条要求，说清经历怎么对上 |

## 三、口语化处理（把书面语改成能说出口的话）

| 简历书面语 | 口述版 |
|---|---|
| 独立主导前端与数据可视化开发 | 这个项目的前端和可视化基本是我在推 |
| 完成约 75 条接口联调 | 大概七十多条接口是我一条条对下来的 |
| 实现图表窗口自适应与全屏适配 | 图表在窗口缩放和全屏下都得正常，这块我重写过两版 |
| 具备端到端交付能力 | 从训练到能用的小工具，这一整条我自己走通过 |

> 注意：口语化只改**表达方式**，不改事实、不改数字口径。

## 四、双语讲稿

- 中文页：五段齐全，200-280 字。
- 英文页：不逐字翻译，按英文面试习惯重写（前置结论、少用排比、动词开头），180-250 words。
- 术语保留通用英文（YOLOv5 / mAP@0.5 / ECharts / SQL Server），不要硬译。
- 中文页与英文页的**数字与结论必须一致**。
