# 项目口述讲稿

使用当前用户确认的事实与目标 JD，按“角色和价值 → 背景问题 → 本人动作与取舍 → 已确认结果 → 岗位关联”组织短稿。完整事实与检查规则见 [权威工作流](../../prompts/02-workflow.md)。

路径：resourceBase.path 向上三级为资源根；个人资料与讲稿放用户选定目录，脚本用绝对路径，不依赖 DSH_CV_ROOT。

- JD 只决定讲述侧重，不能提供个人史实。仅确认“协助测试”时，不得补成接口测试、Redis 测试、整理报告或修复故障；具体对象、方法和产出未知就保留为待补，不代答。
- 参与、协助均可口语化说明，不强制改成我主导/我独立完成。已确认的深度贡献可以讲透，不因追问风险自动弱化。
- 估计与 pending 数字不入稿。用户口头明确确认可以作来源，但材料未核验须分开记录；不能用蓝本或旧讲稿自证新事实。
- 材料原文缺失时给明确标为待补的短骨架，不把占位当成可直接使用的完整事实稿。
- 稿后附适量真实经历追问或知识题，题型明确，练习答案不写回事实。

落盘 Markdown 后用 audit-facts.mjs --profile <事实文件> 检查；命中仅代表数字 token 出现，仍核对语义。中英文版本的事实和数字一致。公共规则只读，个人写法笔记放本人目录。

按需参考 [讲稿模板](references/pitch-template.md) 与 [岗位角度](references/role-angles.md)，示例均不能充当本人来源。
