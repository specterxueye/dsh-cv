# 项目讲稿（Project Pitch Script）

把同一段经历，按**目标岗位的考察点**讲成 90-120 秒的口述稿。投 AI 应用开发要讲"模型到应用的闭环"，投数据可视化/前端要讲"真实政务项目里的交付与适配"，投央国企要讲"稳定性 + 规范 + 团队协作"。

> **路径约定**：仓库根 = `$env:DSH_CV_ROOT`。相对路径以仓库根为基准；命令在仓库根执行。

## 1. 纪律（最高优先级）

1. **只吃事实源**：讲稿里的每一个事实与数字，必须来自 `users\<用户名>\<名字>-事实基线.json`、`<名字>-事实溯源清单.json`、`<名字>-画像.md`、`项目素材库.md`、已验证蓝本，或用户本次口头确认。**不许为了"讲得漂亮"补细节**——面试官会追问到底。
2. **数字必须过审计**：讲稿落盘后跑
   `node "scripts\audit-facts.mjs" "<讲稿.md>" --user "users\<用户名>"`
   未命中的数字 → 补来源或删掉。讲稿里编的数字，比简历里更危险（会被当场追问）。
3. **讲"我怎么判断"，不只讲"我们做了什么"**：面试官要的是你的决策与判断（为什么这么选、当时还有哪些方案、代价是什么），不是团队流水账。
4. **口语化不等于随意**：允许短句、口语连接词；但禁用"参与了/协助了/帮忙做了"这类弱化词，改用"我负责/我判断/我推动/我实现"。
5. **避雷点（内部资产）不进口述**：`画像.md` 的避雷点用于**风险预判**，不能变成讲稿内容。

## 2. 输入

| 项 | 说明 |
|---|---|
| 目标 JD | 文字或图片；若能拿到 `output\jd-<公司>-<岗位>.json` 直接读（含 keywords/gapList/companyStyle） |
| 选材 | 默认从蓝本已显示项目 + `项目素材库.md` 选 **2-4 个**最相关；**换项目要先问用户**（同工作流阶段 3 的确认门） |
| 语言 | 默认中文；用户要英文或双语时 → 双语（每项目中文页 + 英文页） |

**未拿到 JD** 时：先问"投的是什么岗位/哪家公司"，不要凭空猜侧重。

## 3. 输出规格（可验收）

每篇讲稿五段，总时长 **90-120 秒**（中文 **200-280 字**；英文 **180-250 words**）：

```
① 开场句（1 句）        —— 一句话点出这个项目的价值与你扮演的角色
② 背景与问题（2-3 句）  —— 为什么做、当时的约束/难点是什么
③ 我做了什么（3-4 句）  —— 聚焦你的判断与动作（含技术选型/方案取舍）
④ 结果（1-2 句）        —— 量化或定性结果；数字必须可溯源
⑤ 与本岗位的连接（1-2 句）—— 主动点出这段经历如何迁移到目标岗位
```

- 每篇后附 **「可能追问」2-3 条**（双语时也给双语），并各写**一句话答题要点**（要点同样受纪律 1 约束）。
- 落盘：`users\<用户名>\output\pitch-<公司>-<岗位>.md`（多项目在同一文件，按相关度排序）。
- 交付时同时给出：**选了哪些项目 / 排除了哪些 / 为什么**（与简历口径一致，避免面试自相矛盾）。

## 4. 按岗位角度切重心

| 目标岗位 | 讲稿重心（③ 段展开什么） | 结尾 ⑤ 的落点 |
|---|---|---|
| **AI 应用 / 计算机视觉** | 数据集构建与标注规范 → 训练/评估方法论 → 指标怎么看（PR/混淆矩阵）→ 如何做成可交互应用 | 能独立把模型做成产品级 Demo |
| **前端 / 数据可视化** | 真实项目里的模块交付 → 图表自适应/全屏/PDF 导出等硬骨头 → 接口联调与超时优化 → 与后端/测试协作 | 能承接真实业务页面与可视化需求 |
| **后端 / 数据库** | 实体建模与范式 → 存储过程/触发器/视图的业务自动化 → 一致性/约束设计 | 能把业务规则落到数据层 |
| **算法 / 测试 / 运维** | 方法选择与对比实验 → 边界与异常处理 → 质量/稳定性手段 | 有可复现的方法论，不是碰运气 |
| **央国企 · 综合信息化** | 项目性质（中标/政务/校企）→ 规范与流程意识 → 跨组协调 → 文档与验收 | 稳定、守规矩、能长期干、服从组织安排 |
| **产品 / 运营** | 发现问题 → 定义方案 → 推动落地（含资源争取） | 有从 0 到 1 的判断力 |

> 更细的映射、追问链与危险区见 `references/role-angles.md`；讲稿骨架示例见 `references/pitch-template.md`。

## 5. 完成判据

- [ ] 每篇 200-280 字（或英文 180-250 words），五段齐全
- [ ] 每篇附 2-3 条可能追问 + 答题要点
- [ ] 每个数字过 `audit-facts.mjs`
- [ ] 选材与简历一致（没讲过简历里没有的项目；简历里的强点都有对应讲稿）
- [ ] 讲稿里的说法与简历措辞不冲突（同一件事两种口径 = 面试自杀）
