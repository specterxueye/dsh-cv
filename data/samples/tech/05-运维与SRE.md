# 运维 / SRE 岗简历规律

> **语料性质说明**：规律提炼，非真实简历原文。例句为通用句式示例（数据为示意占位）。
> **来源方向**：简历网《SRE简历这么写，系统稳、效率高的实力一眼藏不住》、设计英才网《技术岗简历项目经历写作指南》（运维正例）、新东方求职指南。

---

## 规律 T-O1：开头一句话说清定位与核心能力主张
- 应聘岗位直接写全称（如"站点可靠性工程师（SRE）"），并加一句技术特长定位：如"专研系统可用性与自动化运维，擅长以监控和流程优化减少故障"。
- **来源方向**：简历网 SRE 文。

## 规律 T-O2：技能必须结合场景，拒绝名词罗列
- 反例："熟悉 Linux 和 Kubernetes"。
- 正例句式（示意）："会用 Linux 做性能调优，靠 Kubernetes 管理容器集群；用 Prometheus + Grafana 搭建监控体系，可提前预警故障"。
- **来源方向**：简历网 SRE 文。

## 规律 T-O3：核心成果叙事三件套：可用性 / 时效 / 成本
- 可用性（99.9%→99.99%）、故障恢复时间（MTTR）、人工操作量、云成本。
- 句式示例（示意）："优化系统架构并引入新监控工具，系统可用性从 99.9% 提升至 99.99%，故障恢复时间缩短 50%""自动化脚本使人工操作量减少一半"。
- **来源方向**：简历网 SRE 文；设计英才网（运维正例：故障响应 30 分钟→5 分钟，可用性 99.9%）。

## 规律 T-O4：项目选型 2–3 个代表项目
- 每个项目写清：背景、技术方案、效果。突出"解决实际问题的思路"而非罗列职责。
- **来源方向**：简历网 SRE 文。

## 规律 T-O5：容灾/高可用叙事
- 多活容灾、自动化演练、分钟级故障切换。
- 句式示例（示意）："设计多活容灾方案，通过自动化演练实现分钟级故障切换"。
- **来源方向**：简历网 SRE 文。

## 规律 T-O6：平台化叙事
- 搭建运维平台整合流程与工具，体现工程化思路。
- **来源方向**：简历网 SRE 文。

## 规律 T-O7：软技能信号
- 故障响应速度、容量规划、跨团队协作——保系统稳定的关键软素质。
- **来源方向**：简历网 SRE 文。

## 规律 T-O8：认证与持续学习信号
- 计算机相关学历、SRE 领域认证、技术博客、开源贡献、行业分享——体现对技术热情与持续学习。
- **来源方向**：简历网 SRE 文。

## 规律 T-O9：按公司需求定制侧重
- 投递前看 JD：看重容灾就多提容灾经验；在意成本优化就多讲成本成果。
- **来源方向**：简历网 SRE 文。

## 规律 T-O10：长度与结构
- 1–2 页内，重点突出、条理清楚；多体现系统性思维与结果导向。
- **来源方向**：简历网 SRE 文。

## 规律 T-O11：IaC 与 CI/CD 叙事
- Ansible、Terraform、自动化部署流水线、灰度发布、可观测性栈（Prometheus/Grafana/日志/链路追踪）。
- 句式示例（示意）："以 Docker + K8s 搭建容器化部署环境，配置 Prometheus + Grafana 实现 CPU/内存/接口异常实时告警"。
- **来源方向**：设计英才网（运维正例）；简历网 SRE 文（工具清单）。

## 规律 T-O12：关键词覆盖（ATS 视角）
- Linux、Kubernetes、Docker、Prometheus、Grafana、Python/Go、Shell、Ansible、Terraform、CI/CD、监控告警、日志分析、性能调优。
- **来源方向**：简历网 SRE 文；腾讯云（ATS 关键词映射思路）。
