# 00-总则（最高优先级，任何规则冲突时以本文件为准）

## 第一部分：通用协作原则（约束"我们"之间的协作，不约束简历内容）

1. **能就是能，不能就是不能**：工作过程中任何能力、成本、可行性问题，如实回答，不迁就、不粉饰、不给虚假预期。此原则适用于本插件的开发协作，也适用于与用户之间的所有沟通。
2. **实事求是**：评估、承诺、预测必须诚实客观，宁可泼冷水也不给虚假预期。

## 第二部分：简历内容纪律（约束"简历正文"写什么）

### A. 简历只写优势与真实成果，绝不写缺点

1. **简历正文中绝对不出现缺点、短板、软肋、待改进项、自我批评**。即使真实存在（如"英语一般""某技能未接触"），也不写。
2. 画像中的"避雷点/软肋"是**内部资产**（`users/<用户名>/<名字>-画像.md`），用于我们内部规避风险（如提醒自己某处经不起深挖、避免编造、投递时避免把本来不强的点放大），**永远不进入简历 JSON 或简历文本**。
3. 同理："JD 缺口"（岗位要求但人物没有的能力）的诚实处理是**写作策略层面的内部决策**（挖掘相近经历 / 弱化不写 / 建议用户补充），只在写给用户的《写作说明》里如实提示，**简历正文不呈现缺口、不写"我缺 X"**。

### B. 真实性（与"不写缺点"并行，不冲突）

1. **绝不编造**：简历中每一个数字、每一段经历、每一项技能都必须可溯源（profile 事实基线或一手材料）。
2. **量化无据不写**：无出处的数字一律不写；宁可写得朴素，不可编得好看。
3. 无据可查的内容降级或不写；**不写缺点 ≠ 可以编造优点**。好简历 = 把真实的优势讲透，而不是把短板暴露或美化。

### C. 写作铁律（对齐优化清单 0-7）

- 每份简历逐条对照 `01-优化清单.md` 落实并自检。
- 结构固定：基础信息（照片）→ 教育经历 → 实习经历 → 项目经历 → 校园经历 → 技能优势 → 自我评价；证书并入技能优势。
- 一页装下（autoOnePage + 内容裁剪双保险）。
- 每行有结果，不流水账；动词开头；数字先行。

## 第三部分：流程铁律

- 先建档（画像落盘 profile/）→ 分析 JD → 写作策略 → 生成 JSON → 诊断，不允许跳过建档直接开写。
- 生成 JSON 后必须运行 `scripts/validate-resume.mjs`，通过才算交付。
- 诊断结论诚实：做到的标 ✅，做不到的标 ❌ 并说明原因——此诚实针对**过程与说明**，不转化为简历上的自我批评。
