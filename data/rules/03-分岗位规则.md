# 03-分岗位规则（通用版 · 岗位类型侧重差异）

> 本文件只讲**岗位类型规律**，与具体用户/公司无关。目标公司画像等个性化信息在 `users/<用户名>/` 下（如 `投递策略-个案.md`）。

## 一、岗位类型与侧重矩阵（通用规律）

| 维度 | 技术开发岗（互联网/民企） | 央国企技术岗 | 央国企综合/信息化岗 |
|------|--------------------------|-------------|---------------------|
| 简历重点 | 项目深度、技术栈新、量化指标 | 稳定性 + 政治面貌/荣誉 + 排名 + 团队角色（比项目深度更受重视） | 政治面貌、文字功底、获奖、学生干部 |
| 项目排列 | 最硬核技术项目置顶 | 政务/国企相关项目置顶 | 综合课设、学生工作 |
| 技能写法 | 最新技术栈放前面 | 强调"能干活、能落地"（真实项目记录） | 办公技能 + PPT 宣讲/公文 |
| 自我评价 | 突出技术深度 | 结论+论证：科班出身、政治面貌、排名、政企项目 | 严谨务实、组织协调 |
| 禁忌 | 空话、堆砌 | 夸大、编造（政审严格） | 脱离专业的表述 |

## 二、央国企简历初筛清单（投递前必查）

1. **硬要素靠前**：党员/预备党员、GPA 排名、专业排名、毕业院校（软科/双一流等含金量标注）、学生干部职务、获奖证书。
2. **稳定性信号**：籍贯/家乡（服从调配意愿）、在校生身份；部分简章要求"能接受倒班/异地/基层"——如有真实意愿可写进自我评价。
3. **荣誉证书**：竞赛/证书/学生荣誉——放技能优势或自我评价，不单独列章节。
4. **政企/公共项目经历是加分项**：真实政务项目、校企合作、政府实习——突出"真实项目、保密协议、甲方部门对接"等真实性要素。
5. **文字规范**：无错别字、排版整齐、一页装下；企业名称写全称。

## 三、投递版本切换规则（一画像多版本）

- **通用原则**：同一画像，不同岗位出不同版本——排序、详略、关键词、自我评价侧重随岗位变。
- **版本类型**：
  - 技术纵深版（研发/算法/AI）：核心项目置顶 + 最新技术栈前置 + 自我评价突出技术。
  - 行业匹配版（政企/制造业/金融信息化）：政务/行业项目置顶 + 合规/保密要素 + 自我评价突出落地与稳定性。
  - 综合基础版（管培/综合/行政）：学生工作 + 文字功底 + 办公技能 + 荣誉前置。
- **切换规则**：技术栈优先展示岗位要求的；无关内容裁剪；关键词逐条命中。
- **趋势注意**：同一画像多版本之间**核心事实必须一致**（统一从事实基线取数，禁止各版本数字打架）。
