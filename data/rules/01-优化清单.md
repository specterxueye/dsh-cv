# 01-优化清单（通用版 · 所有用户的简历统一验收标准）

> **★★★ 标准参照（最高优先级素材）**：`data\samples\standard-机构简历样例.md` —— 用户提供的机构改写样例（信息全不冗余 / 每点只出现一次 / 加粗克制 / 技能能力域分区 / 实习三段量化 / 校园两段学生工作 / 自我评价结论式不重复）。**写作前必读；形态冲突处以该样例为准。**

> 本文件是**方法论骨架**，不含任何个人数据。某用户的个性化要求（关键词清单、目标公司、量化数字锚点等）存放在 `dsh-cv/users/<用户名>/优化清单-个案.md`，由该用户自己的会话读取。
> 写作时：通用规则 = 本文件 + 00-总则 + 02-范本五规律 + 03-分岗位规则；个性化 = users/<用户名>/ 下文件。
> 全库唯一事实源：`users/<用户名>/事实基线.json`（每条事实须可溯源）。

## 0. 简历结构（章节，固定顺序）
基础信息（照片）→ 教育经历 → 实习/工作经历 → 项目经历 → 校园/实践经历 → 技能优势 → 自我评价。
- **证书不单独列章节**：证书类（语言/专业认证）并入"技能优势"。
- 荣誉奖项可作独立自定义区块（在校园经历/技能优势之后）或并入技能/教育；按用户名下个案约定。

## 1. 关键词抓取 + 加粗（过初筛）
- 从目标 JD 提取 3-10 个核心关键词（技术栈、框架、协议、证书/认证、学校/级别、岗位术语），在简历中**逐条命中**（用 Ctrl+F 自查）。
- 关键词用 `<strong>` 加粗，**至少在基础信息/教育经历/技能优势出现**。
- 关键词必须**真实会**：只写真实掌握的；侧重展示 ≠ 造假。

## 2. 教育经历
- 格式：`起止 · 学校 · 专业（学历）`；学校/专业全称（对照学信网）。
- **GPA + 排名**明确写入（有则写，无则省略成绩相关表述）。
- 主修/核心课程**对齐目标岗位**（裁掉无关课）；荣誉（奖学金/竞赛）一句话带过不展开。

## 3. 实习/工作经历（重点）
- 时间、单位（全称）、职位写清；**背景层**交代项目性质/级别（真实项目、中标项目、校企合作等）。
- **角色 + 责权**：组长/副组长/核心开发等明确写出。
- **量化优先**：开发记录/模块数/接口数/覆盖范围/团队规模/耗时优化——每行都有结果，避免纯流程描述。
- **量化必跟 Impact**：每个量化数字之后必须写"导致了什么结果/起到了什么作用"（动词：保障/支撑/形成/替代/得出……），如"完成 75 条接口联调（…），**保障 20+ 模块按期上线交付**"；Impact 必须是可推知的真实业务/功能影响，**禁止编造"提升 30%"类无据数字**。
- 技术栈一句话（版本号可选）；突出保密/合规等真实性要素（如涉及）。

## 4. 项目经历（标注级别 + 量化）
- **素材库按岗位择优显示**：写简历前先查 `users\<用户名>\项目素材库.md`，按 JD 关键词选 2-4 项核心项目（相关性排序、核心置顶、≤4 项一页约束）；**未显示 ≠ 删除**（保留素材库备查），用户明确排除项（社会实践/预科等）永不显示。
- **标注项目级别**：真实项目（X 单位中标）/ 课程设计 / 课程实验 / 竞赛 / 大作业——不夸大。
- **角色与项目分离**："角色（来源性质）"，如"前端负责人（真实政务项目）"。
- **量化指标**：数据规模、准确率/指标值（可复现）、功能点/模块数、文档/产出数量；指标必须能从项目材料复现。
- **量化必跟 Impact**：指标后补一句结果/作用（"形成可复现评估基线""得出满足约束的最优方案"等），课设/实验类写明"验证了可行性/形成基线"等真实结论。
- 材料存疑的（如论文中引用他人的对比数据）**标注口径**（"论文+课程设计"而非"实测"）。

## 5. 校园/实践经历（重写为实习格式）
- 标题：`（在校期间）<组织/项目名> + 角色`。
- 写法：**我做了什么 → 量化 → 保障了什么**；用词"主导/负责/统筹"，不用"参与帮助"。
- 学生工作/志愿/社会实践以"角色 + 量化 + 结果"呈现；荣誉称号可量化提名次数/持续时间。

## 6. 技能优势（证书并入 + 分层）
- **证书并入**：语言能力（CET 分数/托福等）、专业认证（职业资格/DX 证书）放技能第一条目。
- **能力域分区**，一项一个标题（对齐 02-范本五规律）：AI 与计算机视觉 / 前端与数据可视化 / 后端与数据库 / 算法与编程 / 工程与工具 / 多媒体与办公……
- **分层**：熟练运用 / 熟悉 / 了解，用词讲究不夸大；工具带具体名称。
- 每项落到"能干什么"（产出），一条一句、先总后分。

## 7. 自我评价（3 行，杜绝空话）
格式：**结论 + 论证**（先价值判断，后证据链）：
1. 专业技术基础：<最有证据的一条：真实项目 + 量化>。
2. 工程落地/协作能力：<团队角色 + 统筹/联调 + 上线成果>。
3. 发展与匹配度：<与岗位最相关的能力 + 希望加入贵公司/符合岗位要求的表述>。
- 按岗位方向调整；**杜绝**"学习能力强/抗压能力强/沟通能力强"等无论证空话。

## 8. 量化优先（贯穿全篇）
数字 > 形容词（"提升 30%"优于"大幅提升"）；对比需有基准；无据不写。

## 9. 一页装下（硬性验收标准）
- `globalSettings.autoOnePage = true` + 内容按"岗位相关性"裁剪（详见 03-分岗位规则）。
- 超载裁剪优先级：通用技能描述 > 次要项目详述 > 低相关课程；核心经历不准砍。

## 10. STAR 结构
情境 → 任务 → 行动 → 结果；行动段强动词开头；每段经历含量化结果。

## 附：事实校准机制（防"单用户污染"与编造）
1. 每个用户一个事实基线（`users/<用户名>/事实基线.json`）：每条事实带 source 溯源；"待确认"项写入前必须经用户确认或改口径；**无据不写**。
2. 用户专属数字/关键词/目标公司清单 → 该用户个案文件（优化清单-个案.md）。
3. 通用规则库中**禁止出现具体用户的姓名/数字/公司**；发现混入立即移出（这是插件质量红线）。
